## What this adds

- UX lane runs the existing `StartApp.OpeningUiCapture --prototype-ux` native WPF harness on the fixed TEST source. Physical mouse/right-click and keyboard menu input exercise context menus; some edit/save/draft transitions use VM or UI Automation invocation. The existing checks and screenshots distinguish those actions. Four item groups and long Hebrew/LTR text are checked at 900x750, 720x750 and 720x400. It covers exact-row editing, one active editor, local cancel/save without launch, minimum-height reachability, row menu placement, unchanged staged draft/Done reachability (not changed-draft retention), ordinary TextBox menu vs row menu, readonly capture lists and store-not-saved-yet assertions. This is real XAML with synthetic store/adapters, not the normal packaged app's complete production startup.
- Capture-policy lane runs the existing real Edge six-tab native fixture. It checks duplicate URL/blank handling, visiting every snapshot tab, UIA original-tab selection restoration after injected tab selection and cursor-position changes, unstable partial result, explicit cancellation before selection/restoration, and timeout with no late selection. Compile-time `STARTAPP_CAPTURE_TRACE;STARTAPP_CAPTURE_TEST` probes inject interleavings. This is not the final distributed binary. The fixture reads public Python/Mozilla/Wikipedia pages in a disposable isolated browser profile, no personal accounts or data. Network/page readiness failures are failures to qualify, not a product diagnosis.

## Evidence and limits

Two disposable hosted Windows jobs, 12 minutes max each, no retries, no new service, no secrets, read-only repository access. Full CI is not rerun. Fixed candidate commit/tree and fresh clean checkout are checked separately from workflow SHA/tree. Before/after bindings include runtime checkout source-byte digests, SDK/image/run/attempt, explicit probe constants and output executable digests. Windows checkout line endings may differ from raw Git blobs and must be reconciled, not treated as unexplained changes. No cross-run pass reuse.

Artifacts upload on success or failure for five days. Existing action/outcome records, store snapshots, geometry, screenshots and logs are preserved. The evidence script fails on missing/false/malformed outcomes, missing/duplicated/unrelated case names against the fixed-source exact name/multiplicity inventory, or incomplete executable identity. The inventory binds raw Git blob digests of both harnesses and their drivers. UX expected labels come from a prior complete run of byte-identical harness source, not reused PASS evidence; capture-policy labels are enumerated from each branch in the fixed source. Fresh full inventories and zero native exit status are required. Runtime review still inspects actions, geometry, stores and pixels, not collector success alone. Counts do not replace inspecting what each action actually checked. Child lifetime is bounded. The existing capture script terminates only its owned fixture processes/profile.

Remaining gaps: independent human exploration, consumer Windows/hardware/display scaling, any user journey outside these existing harnesses, live beta publisher/source enrollment/site/download/installation, and complete functional acceptance. The main TEST pipeline's ZIP remains a distinct artifact with its own hash and smoke evidence; neither lane claims to exercise those exact packaged bytes. Yehonatan can review requirements and concrete outcomes and identify gaps; this does not claim he interacted with Windows himself.

Both source reviews are required before the feature push. No DEV/TEST/MAIN merge, website change, publication or release is part of this qualification. New requirements or failures must be returned for a scoped decision, not silently fixed in the candidate.
